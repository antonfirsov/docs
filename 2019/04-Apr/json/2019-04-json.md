## Integration with ASP.NET Core

### Integration with ASP.NET Core MVC
In ASP.NET Core 3.0-preview5, MVC adds supports for reading and writing JSON using System.Text.Json. The System.Text.Json serializer can read and write JSON asynchronously, and is optimized for UTF-8 text making it ideal for REST API and backend applications.

We profiled the performance of reading and writing JSON in ASP.NET Core MVC using Newtonsoft.Json, the serializer used by default in all previous releases, and System.Text.Json for varying payload sizes. Here's the model that was used:

```C#
public class WeatherForecast
{
    public DateTime Date { get; set; }

    public int TemperatureC { get; set; }

    public string Summary { get; set; }
}
```

**JSON deserialization (input)**

|                       Description |     RPS | CPU (%) | Memory (MB) | 
| --------------------------------- | ------- | ------- | ----------- | 
| Newtonsoft.Json - 500 bytes | 136,435 |      95 |         172 |       
| System.Text.Json - 500 bytes | 167,861 |      94 |         169 |       
| Newtonsoft.Json - 2.4 kbytes |  97,137 |      97 |         174 |      
| System.Text.Json - 2.4 kbytes | 132,026 |      96 |         169 |     
| Newtonsoft.Json - 40 kbytes |7,712 |      88 |         212 |           
| System.Text.Json - 40 kbytes |16,625 |      96 |         193 |         

**JSON serialization (output)**

|                       Description |     RPS | CPU (%) | Memory (MB) | 
| --------------------------------- | ------- | ------- | ----------- | 
|  Newtonsoft.Json - 500 bytes |   120,273 |      94 |         174 |    
| System.Text.Json - 500 bytes | 145,631 |      94 |         173 |      
|  Newtonsoft.Json - 8 Kbytes | 35,408 |      98 |         187 |        
| System.Text.Json - 8 Kbytes | 56,424 |      97 |         184 |        
|  Newtonsoft.Json - 40 Kbytes |  8,416 |      99 |         202 |       
| System.Text.Json - 40 Kbytes | 14,848 |      98 |         197 |       

For the most common payload sizes, System.Text.Json offers about 20% throughput increase during input and output formatting with a smaller memory footprint.

To start using these formatters in your 3.0 preview applications, simply modify your application startup to not register MVC's integration for Newtonsoft.Json based features:

```diff
public void ConfigureServices(IServiceCollection services)
{
    ...
    services.AddControllers()
-       .AddNewtonsoftJson()
    ...
}
```
 
 Options for the serializer can be configured using `MvcOptions`:
 ```C#
 services.AddControllers(options => options.SerializerOptions.WriteIndented = true) 
 ```

 ** Known issues **

 * Support for Swagger (NSwag and Swashbuckle.AspNetCore) when using System.Text.Json is ongoing and unlikely to be available as part of the 3.0 release.
 * System.Text.Json added support for serializing dictionaries (`IDictionary<TKey, TValue>`) in 3.0-preview5. Support for dictionaries with complex (non-primitive) values
 and will be available in the next preview release.

### Integration with SignalR
System.Text.Json is now the default Hub Protocol used by SignalR clients and servers starting in ASP.NET Core 3.0-preview5.

 ** Known issues **
- Dictionary support is limited to primitive types
- There are only a couple of exposed options that will be expanded on
- `object` is not supported by the deserializer, so hub methods and client `.On` handlers can't accept `object`
- Some types like `GUID` aren't supported
Please try it out and file issues if you find anything not working as expected.
 
If you would like to switch back to the previous default of using Newtonsoft.Json then you can do so on both the client and server.

1. Install the `Microsoft.AspNetCore.SignalR.Protocols.NewtonsoftJson` NuGet package.
2. On the client add `.AddNewtonsoftJsonProtocol()` to the `HubConnectionBuilder`:
```csharp
new HubConnectionBuilder()
    .WithUrl("/chatHub")
    .AddNewtonsoftJsonProtocol()
    .Build();
3. On the server add `.AddNewtonsoftJsonProtocol()` to the `AddSignalR()` call:
```csharp
services.AddSignalR()
    .AddNewtonsoftJsonProtocol();
